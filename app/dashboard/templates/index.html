Detection steps

How a capture window is analysed

  1. Check flow rules. Look at packet rates, SYN and RST counts, ICMP traffic, and the number of destination ports.
  2. Run Isolation Forest. Check 14 numeric features for unusual combinations. The result is an outlier flag, not an attack probability.
  3. Check repeated behaviour. Compare the source with recent windows to see whether unusual activity continues.
  4. Record the result. Combine the evidence into a window score and save a simulated response decision.
These checks can produce false positives. Inspect the flow before drawing a conclusion.

Simulation only: these are recorded decisions. The project does not block traffic or change firewall rules.

Real-Time Network Traffic Monitoring and Intrusion Detection System

This Computer Networks project captures packets from a selected network adapter, groups them into flows, and stores the results in SQLite. The dashboard displays protocol statistics, traffic rates, and possible intrusion indicators.

The main technologies are Python, Scapy, Flask, SQLite, Pandas, and Scikit-learn. The interface uses HTML, CSS, and JavaScript.

Implemented features

  • Capture and analyse IPv4, IPv6, TCP, UDP, ICMP, ICMPv6, ARP, and decoded DNS traffic.
  • Display directional five-tuples, packet sizes, TCP flags, and estimated traffic rates.
  • Check flow rules, destination-port fan-out, ML outliers, and repeated activity across windows.
  • Search stored flows and export CSV records or a JSON summary.
  • Demonstrate subnetting, CRC, Internet checksum, Hamming code, and OSI layers.

Limitations

  • Traffic rate is calculated from captured bytes and time buckets. It is not a measurement of link capacity or application goodput.
  • Latency and packet loss are not measured by the stored flow records.
  • Common-port service labels are hints. DNS marked “decoded” was identified by Scapy. Encrypted payloads are not inspected.
  • Routing and TCP congestion control are discussed as concepts, rather than implemented as protocols.
  • The supplied ML dataset has 166 rows. It is a small academic baseline. Response actions are simulated.

Capture controls

Choose the Wi-Fi or Ethernet adapter carrying your traffic. Flow records are saved locally and the dashboard refreshes every five seconds.

Live capture on Windows requires Npcap and permission to access the adapter. Monitor only networks you are authorised to use.

Capture or ML not starting?

Check data/capture.log. Run python main.py --train-model if the ML model does not load. On Windows, reopen the terminal as Administrator if Npcap requires it.

Saved records remain available when capture is stopped.
